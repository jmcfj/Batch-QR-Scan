# Batch QR Scan · 批量扫码

Windows 中文桌面软件，批量识别图片和 PDF 页面中的二维码、条形码。本地识码与原码对照无需联网；微信实读试验功能使用已登录的微信与点餐小程序。

## 微信实际读取（试验功能）

此模式独立于后台原码对照：目标是逐个通过已登录的电脑版微信打开点餐小程序，读取页面明确显示的「桌号：…」。**批量端到端兼容性仍需在实际微信版本上验证，不能将自动测试通过等同于所有桌台码可读。**

1. 添加排版图/PDF 并完成本地扫描。
2. 在微信中通过「+ → 写笔记」新建一个专用空白笔记，放大窗口并保持打开。关闭旧的图片预览。需要已登录的电脑版微信，Windows 桌面保持解锁。
3. 点击「微信实读（试验）」。程序会把每个二维码单独重新生成为一张图，粘贴到这个专用笔记中，打开预览并校验码内容，再使用微信「识别图中二维码」。不会向联系人或群发消息；临时笔记会保留并可能通过微信同步。
4. 新的小程序窗口出现并稳定显示唯一的桌号后，记录台号和页面截图，关闭本次打开的小程序与图片预览，处理下一个码。相同码在同一批只读取一次，再回填所有对应记录。
5. 读取期间不要操作微信和鼠标。按 F8 或软件「停止」可中止；检测到窗口切换、预览码不一致、多个新窗口、授权/登录、没有明确桌号或超时，会停止后续队列，保留现场。程序不会选择就餐人数、开台、下单或付款。

实际读取会清空本批旧的“实际台号”，不会用后台文件名或上一页台号填补读取失败。成功的依据为「微信实际页面」，可从 `live_evidence` 字段找到截图；每次运行的单码图、页面截图与关联 JSON 存放在 `%LOCALAPPDATA%/BatchQRScan/evidence/`。当前严格比较台号文本，`C06` 与 `C6` 会标为不同，请人工判断前导零是否属于同一台号。

依赖微信页面的无障碍文本和图片菜单。不同版本、平台限制、无法在电脑版打开的小程序或仅允许手机访问的码可能失败；这类记录不会标为已读取。当前仍保留 CSV/后台原码作为另一种核对方式，但不会覆盖微信实读结果。

本机实测：美团单码自动流程成功读取到 A1 并保存页面截图。连续队列测试受到窗口切换打断，尚未完成连续多码实测；初次使用建议先用少量码验证。原先收钱吧 dId 桌台码并未因此证明兼容。

## 常规扫描

双击根目录的 `启动软件.bat`，或直接运行 `dist/BatchQRScan/BatchQRScan.exe`。
打包后的 `BatchQRScan` 整个目录需要保留，不能只复制 EXE。

1. 添加多个文件，或选择文件夹递归导入。重复路径自动跳过。
2. 也可使用 Win + Shift + S 截图，再点「粘贴截图」。
3. 点「开始扫描」。每次开始会重建结果；每页可识别多个码，保留页码与位置。
4. 可停止扫描，已完成的记录保留。停止需要等待当前页解码完成。
5. 搜索文件名、内容、码类型或状态；勾选「仅已识别」过滤空白和失败记录。
6. 选中结果查看完整文本与路径，支持多选复制或 Ctrl+C。
7. 导出全部结果为 UTF-8 BOM CSV 或 JSON；包含未发现码和失败记录，不受筛选影响。

## 餐厅桌台码核对（默认模式）

### 推荐：导入后台原始桌台码

如果后台导出的原始码按台号命名（例如 `A01.jpg`、`A02.jpg`），点击「导入后台原始码文件夹」，选中该目录。程序会逐个解码原始文件，建立“二维码完整内容 → 后台台号”的对照，无需手工制作 CSV。每个文件应只含一个码；同一个码被命名为多个不同台号时会报告冲突，整个导入不会生效。非图片/PDF 文件自动跳过。

随后添加待检查的排版图或 PDF 并扫描，即可显示对应码的后台台号，以及与印刷台号的比较。把两个码放反时，即使印刷台号看起来正常，也会显示实际对应的另一台号并标红。按完整二维码内容匹配，不按数字顺序推算，也不只比较 dId，避免跨门店误配。

后台台号对照会保存在本机 `%LOCALAPPDATA%/BatchQRScan/reference.json`，重新打开软件仍可使用；更换门店时重新导入对应原码文件夹。该文件及用户原始二维码不会提交到 GitHub。台号依据会标注为「后台原始码文件名」，表示与这批后台原码一致，不表示实时查询了平台最新配置；后台修改绑定后应重新导出并导入原码。

勾选「识别码上方的印刷台号」后，使用本地 OCR 读取码上方的 A01、A02 等字母加数字编号，根据位置配对二维码。每个码独占一行，显示印刷台号、实际台号、核对结果和内部桌台 ID。读到台号但没发现对应码的记录也会列出。OCR 结果需要人工复核；当前自动配对适用于正向排版、台号在二维码上方的桌牌，不支持任意旋转或任意位置文字。

**印刷台号不代表扫码实际台号。** 收钱吧 `dId` 等字段是内部 ID，不能按其顺序推算 A01、A02。如果码内只有内部 ID，实际台号显示「未取得」、核对结果显示「待核实：缺少实际台号」。软件不会把待检查图片当作正确答案。

如有独立的后台数据或微信已核实台号，可导入 UTF-8 CSV，列名必须是 `url,actual_table`。按完整网址精确匹配，不跨门店推算 ID。导入后会重新核对现有结果：一致显示绿色，不一致显示红色，未取得独立台号显示黄色。不要用待检查图片的印刷编号自行制作“正确”对照。链接明确含 `tableName` / `deskName` / `table_name` / `desk_name` 参数时，会显示参数中的台号，并标注依据为「链接台号参数」；这仍是链接声明的名称，不是服务端验证。

当前版本不读取微信小程序私有数据，也不绕过平台登录。点餐链接返回 404 或台号仅在微信小程序内展示时，需要平台后台清单或人工扫码核实结果才能完成核对。

导出 CSV/JSON 包含 `printed_table`（印刷台号）、`actual_table`（实际台号）、`table_id`（内部 ID）、`table_check`（核对状态）及 `table_evidence`（台号依据）。

## 网址二维码：查看网页内容（可选）

「扫描后打开首个网页」默认关闭。手动勾选后，扫描结束会在系统默认浏览器中打开首个识别到的 HTTP/HTTPS 网址。其他网址可选中后点「打开网页」、双击对应行或按 Enter 打开；停止扫描时不会自动打开。

支持 `http://`、`https://` 和 `www.` 开头的网址。普通文本仍显示原文。网页需要联网；需登录的页面会在浏览器中要求登录。微信专属小程序或私有协议不能直接当作普通网页打开。

图片格式：PNG、JPEG、BMP、WebP、TIFF、GIF；TIFF/GIF 会逐帧扫描。
码类型由 ZXing-C++ 提供，包括 QR Code、Code 128、Code 39、EAN、UPC、Data Matrix、PDF417 等。
同一内容出现在多个页面或多个位置时分别保留，便于溯源。

## 限制

- 密码保护、损坏或不可读文件显示失败信息，继续处理后续文件。
- PDF 以约 216 DPI 渲染，单边最高 6000 像素；极小、模糊或遮挡的码可能无法识别。
- 当前版本面向本地图片和 PDF，不包含网页 URL 抓取或摄像头扫描。
- CSV 对可能触发表格公式的内容添加前置单引号；JSON 保留原始文本。

## 开发与检查

Python 3.12，Windows 10/11。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe app.py
.\.venv\Scripts\python.exe -m pytest -q
.\build.ps1
```

自动检查覆盖：同图多码、二维码/Code128、多页 TIFF、多页 PDF、空白页、文件错误、取消、导出保护、桌面导入/后台扫描/筛选/复制。
